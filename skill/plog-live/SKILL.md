# PLOG·日常奇遇

让一张真实日常照片发生一件不可能的小事。照片保留生活质感，新增元素承担动作和惊喜。

本技能仅供用户明确调用。不得因出现“照片”“动态”“PLOG”等普通词语自动启动。入口配置使用 `policy.allow_implicit_invocation: false`。

## 当前能力与边界

- **可运行：纸云串雨。** 深蓝不规则纸云下垂细线，细线上串有灰蓝、深蓝、白色水滴和少量砖红色水滴；线与水滴像手工悬挂物一样轻摆。它不是仿真的降雨粒子。
- **设计配方，尚未实现：** 流星、亮片山水、泡泡、飞鸟、雪花、月亮、拼图。不得把配方写成已经可导出的效果，也不得静默改用纸雨代替用户点名的效果。
- 支持原照片输入；主题生成底图属于另一路径，必须在交付说明中标明“生成底图”。不得把生成照片称为用户实拍。
- 默认静止照片与装饰分层。人物、手、食物、家具和原有文字不随动画变形。
- 推荐以 3 秒、每秒 30 帧、3:4 竖幅起步；这些是本项目的创作默认值，不是苹果实况照片的普遍格式限制。
- 最终目标是苹果实况照片（Live Photo）。普通视频和配对文件都不能单独证明其已在照片应用或手机上可用。
- 首版场景输入接受 PNG、JPEG、WebP；其他格式不自动转换或重绘。原生配对工具当前要求 macOS 26 或更高版本及可用的苹果 Swift 编译器，这是本工具的实现限制，不是实况照片格式的通用要求。

## 图像工具与代码的分工

1. 用户原照片由场景创建脚本直接复制。原件不覆盖，复制不能夹带自动裁切、调色、锐化、修复或重绘。
2. 生成或编辑位图，只允许使用 Codex 宿主内置的 `image_gen.imagegen`。包括主题底图、照片修图、抠图、去背景，以及独立纸纹或复杂手绘位图素材。
3. 内置工具不可用或失败，就明确说明阻塞原因并保留已有文件。不得安装、调用或恢复第三方生图技能，不得通过 API、命令行、脚本或本地模型替代。
4. 代码可直接定义场景原生的矢量云朵、细线、水滴和动作，用于可编辑、可重复播放的动画。它们是动画图形；不得借此把照片重绘或位图修图改走代码路径。
5. 原生形状用曲线、填色和少量边缘不规则表达剪纸感。需要独立的真实纸纹图片或复杂手绘图案时，转交内置图像工具，不用本地程序生成替代位图。
6. 场景播放、按固定时刻渲染、视频编码及写入实况照片配对信息属于动效制作流程。它们不授权修改原照片内容。

## 工作流程

### 1. 确认输入与小事件

先判断用户提供的是原照片、参考截图，还是只有主题。

- 原照片：保留原件，读取尺寸与方向，围绕现有光照和留白安排装饰。
- 参考截图：只分析照片和装饰语言；界面、评论、字幕、播放按钮、平台标识和其他叠字都排除。截图不能证明原动作的速度和循环方式。
- 只有主题：用内置图像工具生成符合摄影规则的底图，并记录来源。调用前遵守当前宿主的工具规则。

用一句话写出事件，例如：“桌边悬着一朵纸云，串着雨滴的细线被微风吹向一侧。”这句话确定支点、运动范围与照片主体之间的关系。

用户已有明确方向时直接制作，不逐张征求重复确认。当前效果无法满足明确要求时，说明能力差距，先处理不依赖新增效果的工作，不把未开发能力包装成成品。

### 2. 建立场景

以下命令均以 **`SKILL.md` 所在的技能根目录** 为工作目录；路径必须替换为真实绝对路径。代理调用时先解析本技能的实际安装位置，不假定它仍位于开发仓库。若从开发项目根目录运行，相应脚本路径为 `skill/plog-live/scripts/`。

```sh
node scripts/create-scene.mjs --photo /绝对路径/原照片.jpg --out /绝对路径/新场景
```

使用已有配置时：

```sh
node scripts/create-scene.mjs --photo /绝对路径/原照片.jpg --out /绝对路径/新场景 --config /绝对路径/配置文件.json
```

创建脚本复制模板与原照片，不重绘照片。未指定画布双边尺寸时，只读源图的尺寸和方向，将最长边控制在 1920 像素内，并生成尽量匹配原比例的偶数尺寸画布；默认不留黑边，也不裁掉主体。只有用户明确配置画布宽、高时，才按指定构图填满画面；这种显示取景可能裁掉边缘，必须核对人脸和主体，源照片文件仍逐字节保留。

配置字段以当前模板和脚本的真实实现为准，不猜测字段名称。修改前确认目标场景属于本次任务，不能覆盖用户已有成果。

根据照片确定纸云支点、线帘长度、避让区域、配色与摆幅。若当前模板没有实物遮挡能力，就让串雨停在留白中；不得宣称它已经穿过杯口或躲到人物后面。

### 3. 离线预览与动作检查

直接打开场景的 `index.html`，使用 `file://` 预览，不启动服务器。预览页面的播放控件遵守 scenes 正本；控件不进入导出的照片或视频。

动作按作品时间计算，来回拖动到同一时刻应得到同一画面。照片保持静止，线的上端随云连接，下端轻摆，串珠不脱离细线。随机差异需要固定，不能每次重播改变布局。

默认不主动截图或进行耗时视觉检查。浏览器操作和截图验收按用户本次授权执行；静态代码检查不能替代用户的实际观感验收。

### 4. 渲染与配对

```sh
node scripts/render-scene.mjs --scene /绝对路径/场景目录 --out /绝对路径/渲染目录
```

渲染使用本机已安装 Chrome 的独立后台实例处理本场景的离线页面，再由 FFmpeg 编码；不启动网页服务器，不操作用户已有浏览器窗口，不读取用户浏览器会话。视频帧直接送入编码器，不把逐帧图像落盘；这一过程是成片渲染，不等于已完成视觉验收。任务结束后关闭本次创建的后台实例。

渲染结果应包括静态封面与短视频。封面须对应视频中的指定时刻，不能另用一个与动画画面不一致的版本。

以当前推荐的 3 秒场景、1.5 秒封面时刻为例：

```sh
scripts/live-photo.sh pack --photo /绝对路径/cover.png --video /绝对路径/preview.mp4 --output /绝对路径/配对目录 --name plog-paper-rain --key-time 1.5
```

`--key-time` 必须落在实际视频时长内；场景时长或封面时刻改变时同步调整，不照抄示例。

`pack` 会同时执行文件检查与系统解码检查，读取它返回的报告，不因文件存在就忽略失败状态。检查已通过且文件没有改变时，无须重复验证；单独复核其他配对资源时使用 `verify` 子命令，示例见实况照片说明。苹果环境、工具链或系统解码不可用时，如实报告停在哪一层，不给失败资源贴上“已可用”标签。

### 5. 交付

交付静态预览页面、静态封面、视频以及已成功生成的实况照片配对资源，分别给出绝对路径和已完成的验证层级。

相册导入会写入用户的照片库。只有用户明确要求加入相册时才调用 `import`；制作技能、制作动效或导出资源本身不等于导入授权。不要为试验自动导入照片。

手机识别、长按播放及目标发布平台兼容性，需要在真实设备和目标应用验证后才能声称通过。若尚未完成，给出简明的人工验收步骤并保留交付物。
